# Requirements elicitation

Help the user clarify a small, testable increment before proposing code. Ask a few focused questions at a time. Capture user roles, core flows, failure/ambiguity behavior, constraints, and acceptance criteria. Distinguish confirmed requirements from assumptions and open questions. For HuePilot, treat the confirmed brief in `AGENTS.md` and the conversation as source requirements; do not invent persistence, remote access, or extra capabilities.

Finish each requirements pass with a concise summary and acceptance criteria the user can approve.
